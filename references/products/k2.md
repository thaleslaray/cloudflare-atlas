# K2

> K2 is a serverless durable event stream (append-only log) on Cloudflare Workers. Producers write records in atomic batches; consumers read via independent subscriptions with at-least-once delivery and lease-based processing. Available only on Workers Paid plans. Currently in Public Beta with a 10 GB per-account storage cap.

## When to use

- Durable event ingestion where producers and consumers must be fully decoupled (multiple independent readers, no competition).
- At-least-once processing pipelines that require explicit ack/nack and lease renewal semantics.
- Binary or structured record streaming with per-record headers (up to 1 MB per record).
- Replacing self-managed Kafka/Redpanda for moderate-throughput serverless workloads within beta limits.
- Event sourcing or audit logs where append-only ordering and configurable retention (1 h – 30 d) matter.

## When not to use

- Simple async job queues with single-consumer semantics — use Cloudflare Queues instead.
- Workloads requiring >10 GB storage or >30-day retention without prior approval (beta caps).
- FIFO/exactly-once guarantees without building idempotency yourself.
- Pub/sub fan-out where messages should disappear after first consumption.
- Streaming analytics over unbounded windows better served by R2 + external compute or Time Series.

## Key API/access patterns

REST base: `https://<STREAM_ID>.k2.cloudflarestorage.com`

**Produce**

- HTTP: POST to `https://<STREAM_ID>.k2.cloudflarestorage.com/produce` with Bearer token; body `{ records: [{ content: "<base64>", headers: {...} }] }`. Content must be standard base64 (not url-safe). Request ≤5 MB.
- Worker binding: `env.ORDERS.send({ content: new Uint8Array(...), headers: { ... } })`. Content must be `ArrayBuffer` or `Uint8Array`, never a string.
- Wrangler config: `[[k2]] binding = "ORDERS" stream = "<stream_id>"`.

**Consume**

- Create subscription once (immutable; same name returns existing ID) with `"start_at": { "type": "earliest" }` — `start_at.type` is `earliest` (oldest retained record) or `latest` (skips records that exist at creation).
- Lease batch: `POST /subscriptions/<id>/consume` with `{ worker_id, max_records }` → `{ batch_id, leased_until_ms }`. Lease duration is 5 minutes.
- Acknowledge: `POST /batches/<batch_id>/ack` with `{ worker_id }`. Advances cursor.
- Negative-ack: `POST /batches/<batch_id>/nack` with `{ worker_id }`. Releases batch for redelivery.
- Extend lease: `POST /batches/<batch_id>/extend` with `{ worker_id }`. Adds 5 minutes; fails 409/10218 if expired.

**Configuration**

- Inputs: enable/disable HTTP and Worker binding independently; never disable both.
- Authentication: when `false`, endpoint is public and CORS is configurable (up to 5 origins or `"*"`). When `true`, Bearer token required and CORS is ignored.
- Retention: set per-stream at creation; PATCH supported for updates. Renaming streams is not supported.

## Gotchas

- Delivery is at-least-once. Consumers MUST be idempotent; error code 10212 means unknown outcome — do not retry without deduplication.
- Timestamps are server-assigned and cannot be overridden by producers.
- Calling `/consume` again with the same `worker_id` before ack/nack returns the SAME batch (lease refresh); `max_records` is ignored on repeat calls. Useful for recovery, dangerous if unintended.
- `ack` and `nack` accept any `worker_id`; `extend` requires the current lease holder.
- Expired lease on extend returns 409/10218 — stop extending and request a new batch.
- Producing from browsers requires `authentication=false` (public endpoint). Validate payload integrity and authorization inside consumers.
- Produce errors return a singular `error` object; consume errors return an `errors` array. Do not assume uniform shape.
- Subscriptions are immutable after creation; you cannot change `start_at.type` or other parameters.
- Stream renaming is not supported. Recreate and migrate if needed.
- Standard base64 only for HTTP produce; url-safe base64 is rejected.

## Pricing & limits

> **Verify on the live pricing page before quoting** (`developers.cloudflare.com/k2/platform/pricing/`, checked 2026-10-12, page dated Oct 6, 2026).

- **Billing is not enabled during the public beta** — Cloudflare promises ≥30 days notice before it starts; rates are published in advance and may change.
- Cost drivers (Workers Paid; uncompressed bytes, 1 GB = 1,000,000,000 bytes): **data produced $0.04/GB** · **data consumed $0.04/GB** (each subscription reads every record, so fan-out multiplies it) · **data retained $0.02/GB-month**. No free tier is listed on the page.
- Storage: 10 GB total per account during beta. Increases available by request.
- Streams: max 20 per account.
- Retention: 1 hour to 30 days (default 7 days). Beyond 30 days requires approval.
- Produce: request ≤5 MB; record ≤1 MB; ≤32 headers per record; header name ≤256 B; header value ≤8 KiB; total headers size ≤64 KiB.
- Consume: `max_records` ≤10,000; response ≤10 MB; `worker_id` 1–256 characters; ≤128 active leases per subscription; ≤100 subscriptions per stream.
- Lease duration: fixed at 5 minutes; extendable in 5-minute increments while valid.
- Plan requirement: Workers Paid. Not available on Free.
