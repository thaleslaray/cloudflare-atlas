# Pages — full-stack apps with git deploys

> Connect a Git repo and Cloudflare builds + deploys your full-stack app to the global network,
> with per-branch preview URLs and file-based serverless **Pages Functions** (Workers runtime).

## When to use
- Git-driven static sites + JAMstack frameworks (SvelteKit, Astro, Nuxt, Qwik, Solid Start) where
  you want zero-config builds, automatic preview deployments per branch/PR, and rollbacks.
- Add dynamic behavior with **Pages Functions** (file-based routing on the Workers runtime) without
  standing up a separate Worker.

### ⚠️ Pages vs Workers — Cloudflare now steers new projects to Workers
The docs frame Pages and Workers as converging, and recommend **Workers for most new full-stack
projects**:
- Workers + **Static Assets** now serves static files (free, like Pages) AND back-end APIs / SSR,
  at a **similar cost structure** to Pages (asset requests free; Function calls billed as Workers).
- Workers has a **broader feature set**: Durable Objects, Cron Triggers, Queues consumers, more
  complete observability, Git-integrated **Workers Builds** — see the official compatibility matrix.
- Cloudflare explicitly routes some frameworks away from Pages: for full-stack **Next.js** the docs
  recommend **vinext on Workers** (Pages is only for a static Next.js export); **Remix** is no longer
  recommended by its own authors — use its successor **React Router** (Workers guide).
- **Bottom line:** prefer Workers for new builds; reach for Pages when you specifically want its
  turnkey Git build pipeline + preview deploys for a supported static framework. There's an official
  **Migrate from Pages to Workers** guide (and a `migrate_pages_to_workers_guide` MCP tool).

## Deploy methods
- **C3 CLI:** `npm create cloudflare@latest` — scaffold + framework setup + first deploy.
- **Git integration:** Dashboard → Workers & Pages → Create → connect GitHub/GitLab → set build
  command + output dir. Auto-builds on push; every branch/PR gets a unique preview URL.
- **Direct Upload:** `npx wrangler pages deploy ./dist --project-name=my-project [--branch=staging]`.

## Binding & config (`wrangler.jsonc`)
```jsonc
{
  "name": "my-pages-project",
  "pages_build_output_dir": "./dist",
  "compatibility_date": "2026-01-01",
  "compatibility_flags": ["nodejs_compat"],
  "placement": { "mode": "smart" },            // Smart Placement (beta, all plans)
  "kv_namespaces":  [{ "binding": "KV", "id": "..." }],
  "d1_databases":   [{ "binding": "DB", "database_id": "...", "database_name": "prod-db" }],
  "r2_buckets":     [{ "binding": "BUCKET", "bucket_name": "my-bucket" }],
  "ai": { "binding": "AI" },
  "vars": { "API_URL": "https://api.example.com" },
  "env": { "preview": { "vars": { "API_URL": "https://staging-api.example.com" } } }
}
```
- Same binding catalog as Workers (KV, D1, R2, DO, Queues, Vectorize, AI, Services, Analytics Engine).
- Secrets: `echo val | npx wrangler pages secret put KEY --project-name=my-project`; local via `.dev.vars`.
- Types: `npx wrangler types --path='./functions/types.d.ts'`. Local dev: `npx wrangler pages dev ./dist`.

## Functions & static config
- **Functions:** `functions/` dir, file-based routing; `onRequest`/`onRequestGet` handlers; middleware
  via `_middleware.ts` (must call `next()`). Or **advanced mode**: a single `_worker.js` (Module syntax)
  takes over all requests and must call `env.ASSETS.fetch(request)` to serve static assets.
- **`_routes.json`** — controls which paths invoke Functions; `exclude` static paths so they stay free
  (auto-generated by most frameworks). Max 100 rules.
- **`_redirects`** (static-asset only) — 2,000 static + 100 dynamic (2,100 total); use Bulk Redirects beyond.
- **`_headers`** (static-asset only) — Functions must set headers on the `Response` instead. Max 100 rules.

## Gotchas
- **`_headers`/`_redirects` don't apply to Function responses** — only to static assets; set headers in code.
- **Functions return 404:** `_routes.json` excludes the path, wrong extension (`.jsx`/`.tsx` → use `.ts`/`.js`),
  or Functions dir not at output root.
- **Bindings undefined:** wrangler config / IDs wrong, missing `.dev.vars`, or stale types — re-run `wrangler types`.
- **`--remote` writes hit real production data** — use only for read-heavy debugging.
- **CPU limit (10ms free)** — exclude static assets from Functions via `_routes.json`; optimize or go Workers Paid.
- **Next.js (full-stack) and Remix are steered off Pages** — see Workers guidance above.

## Pricing & limits
> ⚠️ Pricing changes — verify on the live page (`developers.cloudflare.com/workers/platform/pricing/`)
> and `developers.cloudflare.com/pages/platform/limits/` before quoting.

**Cost drivers:** static-asset requests are **free and unlimited** (both plans). **Pages Functions
billed on the Workers Standard usage model** — you pay per Function request + CPU time (free tier
included; same rates as Workers). No charge for the build pipeline itself beyond build-count limits.

**Key limits (Free plan unless noted):**
- Builds: **500/month**, 1 concurrent (Free) · 5,000/mo, 5 concurrent (Pro) · 20,000/mo, 20 (Business);
  build **timeout 20 min**.
- Files per site: **20,000** (Free) → 100,000 (paid, set `PAGES_WRANGLER_MAJOR_VERSION=4`); max file **25 MiB**.
- Custom domains/project: 100 (Free) / 250 (Pro) / 500 (Business+).
- Preview deployments: **unlimited**. Projects/account: **100** (not routinely increased).
- Functions (Workers limits): CPU **10ms/req** (Free) → 30s default / 5min max (Paid); script **64 MiB uncompressed**
  (Free and Paid, no compressed limit); subrequests **50/req** (Free) → 10,000 (Paid); memory 128MB.
